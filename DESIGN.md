# Design direction

Mode: Operate. A calm, Chinese-first remote coding conversation workspace. The user's DeepSeek references pin the design direction.

Desktop: 280px themed sidebar (260px at intermediate widths), blue wordmark that starts a new conversation, and on-demand search. There is no duplicate expanded-sidebar new-conversation button. Navigation follows the locally installed Codex/ZCode: 30px desktop conversation rows, 14px titles, 8px corners and neutral hover/selected surfaces. The welcome screen ports the www.deepseek.com hero from its source (src/components/HeroBackdrop.vue): a WebGL checks-swirl shader (#8AA3D6/white) and a dotted 90px grid canvas over a #9cc1e7 wash, a 46px weight-400 task prompt with normal tracking, an opaque themed composer that covers the attached island overlap, and restrained translucent suggestion pills. Copy stays minimal: no taglines or repeated reassurances; install lives behind a small icon in the sidebar footer. The chosen background remains visible during conversations; animated scenes receive a subtle theme-aware readability veil: pale-blue user bubbles, 16px/28px assistant text beside a round outlined avatar, and compact unboxed tool activity.

Mobile: an accessible navigation drawer, full-width workspace, bottom-safe composer, full-screen connection editor.

Colors (DeepSeek dsw tokens): brand #3964fe (hover #5686fe), soft #edf3fe, tint #e4edfd, ink #0f1115 / #1e232c, muted #61666b, subtle #81858c, caption #adb2b8, sidebar #f9fafb, borders rgba(0,0,0,.1), hover rgba(38,49,72,.06). Action buttons and single-line dialog inputs are pill-shaped; dialog inputs use the shared full radius on a #f9fafb fill, as on the DeepSeek sign-in page. Status is always labeled, never conveyed by color alone.

Shared geometry: button-opened menus and select lists use the same menu-surface and composer-menu-item styles: 16px panel corners, 8px panel inset, 8px option corners, 8px/12px option padding, and at least 44px option height. The inset keeps inner and outer corners aligned. Model, permission, device, project, conversation-action, changes, settings, and task-grouping menus inherit these tokens instead of setting local shape or row-height overrides. Select triggers follow the existing pill controls; text/code areas retain 12px corners. Standard dialogs use 24px desktop / 16px mobile padding; split-pane settings and fullscreen workspaces retain their structural layouts. Use the shared 4/8/12/16/24px spacing scale for reusable control geometry, with visible inset keyboard focus for menu options.

Typography: self-hosted DM Sans for Latin, PingFang SC / Noto Sans CJK SC / Microsoft YaHei for Chinese. 14–16px body, 46px weight-400 welcome prompt: “有什么需要帮忙？”. Code uses platform monospace.

States: disconnected, connecting, connected, reconnecting, error; no sample data presented as real. Clear inline errors, pending approval controls, offline and update feedback.

Motion: a short ease-out composer reveal; ordinary 160ms controls. Respect reduced motion. Accessible native dialogs, focus indicators, labeled icon buttons, 44px touch controls.

Composer: keep the established blue/white DeepSeek visual language, informed by the locally installed ChatGPT/Codex App 26.928.20755 interaction code. The model menu and reasoning slider are separate controls, beside a live context-usage ring and send/stop controls. Permission selection remains on the left. Controls remain editable during execution; changed settings apply to the next submitted/queued turn. No permanent instructional footnote below the composer. A standalone folder control above the bordered composer explicitly selects the new conversation's working directory.

Device information appears only in a dropdown at the top right. Each device row has its own edit button; adding a device is a separate final menu option. Connected status is green. The entire row shares one hover background; nested buttons do not add another layer.

Sidebar: project folders directly group conversations by cwd, with collapsible groups, indented titles, neutral selected-row fill, archive action and expansion for longer lists. Keep rows flat without a tree rail or stacked highlight backgrounds. Project creation and conversation archive actions appear on hover/focus; touch layouts retain visible actions and 44px rows. Folder/caret share one slot, and queue counts stay unboxed. The sidebar header carries search and collapse controls; search opens explicitly and Escape closes it and restores trigger focus. The collapsed view keeps a compact control capsule for expand/search/new conversation. Project names come from actual paths, never fabricated examples.

Content defaults to 1080px with browser-persisted width presets, a 720–1600px slider and full-window mode. Both messages and the composer follow the same width while retaining responsive gutters.

Prompt input and user messages preserve the order of text and images. Images appear as inline thumbnail/name chips, with hover preview and tap/click enlargement. The editable region uses native selection ranges and plain-text paste handling; image filenames round-trip through the App Server text_elements placeholder mechanism. User bubbles size naturally and do not reserve a separate thumbnail grid or empty block.

Queued messages sit inside the attached composer island, above its project/approval content, with edit/remove and pause/resume controls and no separate card. Queue identity includes device and conversation; failures retain the message and require manual continuation. Collapsed tool details mount heavy contents only when expanded.

Long conversations initially display 60 recent items and load older pages on demand while retaining scroll position. Loading offers cancel and recoverable failures offer retry. Late responses never replace a newer selection. Reasoning handles both summaryTextDelta and textDelta, plus historical summary/content. Display a compact CLI-style live preview and elapsed time only when timestamps exist. Retryable Codex errors replace the working-status text; fatal errors remain actionable errors. Context usage uses server-reported last-turn totals/window limits and exposes available token counters, without inventing tool/skill/system percentages.


Appearance supports light, dark and system modes through root-level tokens, including teleported menus and dialogs. Dark mode uses neutral charcoal surfaces, retains restrained blue controls, and uses a low-luminance blue/charcoal palette for the animated workspace backdrop. Preference persistence preserves width and unrelated saved keys.

The composer now has an attached island: a full-width shallow project shelf inset from the input edges; when requests are pending, the shelf expands upward into one scrollable approval/Ask card. Counter/arrows navigate without discarding unfinished answers. Successful resolution advances by ID; failed submission does not remove the card. Focus after advancing is neutral, not an automatically armed approval button. The project menu is one simple surface with search, folder rows and two actions, with no permanent path form or stacked popovers.

User messages have edit and withdraw actions. Editing is inline and preserves mixed text/image content. Before committing, the UI states that later conversation history is replaced and existing filesystem effects are not reverted. Uncertain/failed sends are never silently retried; recoverable edited text returns to the composer. Empty/whitespace-only reasoning entries render nothing. Context compaction replaces the working status with “压缩上下文中”; completed compaction gets a compact status line, never raw JSON.

Motion refinements: continuous pointer movement on the effort slider, eased snapping to supported effort levels on release, and whole-level keyboard steps. Menu opening/closing, queue insertions and island request changes use short bounded transitions. Respect prefers-reduced-motion throughout. Web queues prefer the daemon’s native persistent queue, shared by clients of the same server. Explicitly unsupported servers retain a labeled page-local queue. The current TUI source still renders its own pending input list and ignores shared queue notifications; do not claim TUI pending-list parity.

Radius system: use --radius-xs (4px) for tiny badges/code/thumbnail corners, --radius-sm (8px) for compact image chips, --radius-md (12px) for rows and ordinary controls, --radius-lg (16px) for menus/cards/previews/message bubbles, --radius-xl (24px) for dialogs/composer/island, and --radius-round (999px) for pills and circles. Icon-only buttons use square dimensions and circular hover/pressed surfaces. The compact header capsule uses the same circle geometry with balanced 3px insets. Mobile and desktop use the same shape scale. Attached island sections retain square joining edges. Define radii through these tokens, including scoped styles and reveal masks, rather than adding component-specific numeric values.

Settings open from the bottom-left sidebar footer in a responsive modal, up to 1040px wide. The left navigation has two separated groups: website settings first (general/content and appearance/background), then Codex settings (model/replies, execution/permissions, context). Only the body scrolls; the header and bottom save bar remain visible. Website preferences apply immediately; Codex changes require the bottom save button. Read config/read with layers and configRequirements/read on demand from the selected device, and save only changed supported keys through config/batchWrite with the user-layer path and expectedVersion. Do not hot-reload active-thread permissions or automatically retry an uncertain write. Show restrictions, version conflicts and unsupported endpoints in the settings surface. Restore trigger focus on close. Auto-connect is enabled by default: after startup authentication, connect the last saved device once; disabling it leaves connection manual, and manual disconnect cancels startup intent. Appearance (light/dark/system) is independent of the selected background mode and image effects. Store one animated/image/plain mode and one image-effects object; migrate old per-theme values once from the currently resolved appearance. Switching appearance, including an OS change, must never switch background mode, opacity, blur or overlay color. Both appearances can render the animated scene, with its palette matching the UI. The canvas remains mounted when entering a conversation; sidebar movement only changes its clipping. Uploaded images also appear behind ongoing conversations; controls and the composer stay solid. Image opacity (0–100%), blur (0–32px), overlay color and strength (0–100%) apply live. Reset restores shared image defaults. Blur overscan prevents transparent edges. Images are rasterized to at most 2560px and saved as a Blob in IndexedDB, not sent to the server or stored in localStorage. Support JPG/PNG/WebP up to 20 MB, storage failure feedback, object-URL cleanup, hidden-page pausing and live reduced-motion changes. Background controls use the shared radius scale; the auto-connect switch has a 44px hit area and keyboard focus.

Working status: append this turn's elapsed time to “Codex 正在工作”, with tabular numerals, seconds below a minute and minute/second formatting thereafter. Prefer the server's turn start timestamp; use a retained local observation time only when that metadata is absent. Do not count pending queue wait time as execution time. Keep the existing separate thinking timer and retry/compaction status text.

Animated workspace canvas geometry is anchored to the browser viewport. Sidebar collapse/expand changes the clipping region and canvas offset, not the shader resolution or grid origin. Only a real viewport-size change reallocates the canvas backing store; avoid redundant width/height assignments that clear the drawing.

Update availability appears in a compact clickable toast below the top-right header, without occupying layout space. It keeps the existing active-task, revision and local-queue update guards. Ordinary action notices keep their bottom toast position.

Shared queue ownership: the daemon alone dispatches acknowledged queued inputs. Queue notifications invalidate and refetch the complete list, reconnect/open restore it, and active-thread polling covers missed notifications. Edit/delete use server queue IDs. Model/effort/permission changes update thread settings for subsequent turns; native queue entries do not carry per-message settings snapshots. Native queue controls do not imply an unsupported persistent pause; idle queues expose an explicit start-next action. Uncertain additions are never automatically retried.


Recent-data scope: project discovery and the task center use the latest observed session activity date and the previous local calendar date. Never anchor to the present clock or scan every old project. Descending recency pagination stops on the first older page; an explicit unsupported recency key falls back to updated time. Search filters the same recent snapshot. The task center groups actual server sessions by project/status/model and reads details without resuming threads. Stop polling when hidden or disconnected.

All selection dropdowns use themed custom controls. The task-center grouping menu stays inside its modal, shares radius tokens, restores trigger focus, supports keyboard navigation and Escape, and respects reduced motion.

Task center: follow the project sidebar's flat, compact navigation. Use neutral selection/hover, 30px desktop rows, 14px titles, 8px row/control corners and unboxed counts. Preserve 44px touch targets. The modal heading is 18px; menu shells use the shared large radius, menu rows the small radius, and status dots the round token. Keep details as aligned text rather than nested cards, and omit absent message/token sections. Actual state labels accompany color.

Archives: a labeled entry above the sidebar footer opens a dedicated archive dialog. Read the backend archive only on request, with 30-row pages and server-side title search. Older archives intentionally remain accessible outside the main list's recent-day window; never eagerly enumerate the whole archive. Restore through thread/unarchive before opening, preserve rows on failure, and reject late replies across devices or closed dialogs. This is server-owned archival, not browser-local hiding or deletion.

Collaborative tools: translate each actual collabAgentToolCall.tool enum into a concise Chinese operation label. Keep call status separate from per-agent status in the data presentation without explanatory prose. Expanded details present real prompt, recipients, model/effort, messages and errors. Omit missing data rather than explaining its absence. Unknown enums remain readable with their original tool name; do not dump raw collaboration JSON.

Commands: expanded commandExecution items highlight shell commands, flags, strings, variables, operators, comments and numbers using separate light/dark syntax tokens. Preserve every original character and escape all input before rendering fixed span classes. Recognize common shell wrappers; heredoc bodies and unsupported syntax stay readable without interpretation. Compute only when expanded and bound parsing for large scripts. Output logs remain plain text.

Markdown code blocks: use the same theme-aware syntax colors for explicitly tagged common languages, including language aliases. Keep each block’s copy button visible, and copy its exact text without the label or highlighting markup. Unlabeled, unsupported and very large blocks retain escaped plain text. Bound highlighting work and cache size during streaming; colors change with the current theme without altering source text or layout.

Composer completion: a line-start slash opens a compact themed command list; a boundary @ searches the active device's cwd. Keep the selection in the editor, support arrows/Enter/Tab/Escape, and suspend during IME composition. Replace only the captured token, preserving adjacent text, image chips and the caret. File mentions insert literal paths, quoting spaces and retaining a trailing separator as the native TUI does. Cancel superseded queries and reject results from a previous device or directory.

Goals: show objective, status, server token usage/budget and elapsed time in a compact row of the composer island. Hide this row during approvals/Ask, retaining the management dialog and drafts. /goal opens the same manager, optionally prefilling the objective. The backend owns execution and persistence; never manufacture percentages or start an extra turn after goal/set. Failure keeps the form, switching threads scopes it, and paused goals may be resumed explicitly.

Tool activity: use transparent compact 28px summaries, close vertical spacing, small icons and shared focus rings. Remove completion checkmarks and status labels; only failures show a red X and 失败. Adjacent equal operations may collapse together; preserve message/reasoning/turn boundaries. Command actions distinguish file reads, directory listings, searches and ordinary commands. MCP identity includes server/tool; collab identity includes its operation. A read group, including a single read, defaults closed with a deduplicated file count. Expanded children retain output and errors. Streaming updates keep stable group IDs and expansion state. Per-agent task status remains independent of tool-call completion.

Conversation inspector: a restrained right-side surface on screens at least 1280px wide, with a header toggle and a modal fallback on narrower screens. Show actual file changes and named subagents, initially six with an explicit more action. Fetch visible agents through read-only, bounded queries; clicking opens inline details, and opening the conversation is a separate action. The output-creation disclosure offers document, presentation, spreadsheet and site requests; choosing appends a prompt to the composer without sending or destroying the existing draft. Do not bind nonexistent desktop plugins or invent generated artifacts. File-change summary is one subtly bordered surface using the large radius, aligned to tool text; show three files initially, real counts when all relevant hunks are recognizable, and mount full diffs only when requested. The summary represents only the latest turn and hides as soon as a new turn begins. Historical file activity remains reachable in the inspector; explicit worktree scopes and a confirmed full-patch undo live in the changes panel.


## Conversation transitions and changes viewer (2026-09-30)

- Home composer area has a fixed 760px maximum outer width, capped by available space; user content-width applies after engagement. Focus/input, project selection or opening a conversation transitions the existing editor to its destination width and bottom position in 420ms using measured geometry, without scaling glyphs or remounting the editor. Returning home resets the compact layout. Resize, unmount and reduced-motion changes cancel stale animations.
- Tool disclosure height, show-more rows, file folds, goal details and inspector entry use bounded 160–260ms motion. Hiding content becomes inert immediately. Reduced-motion users get immediate layout changes.
- File type icons retain conventional language colors; all diff additions/counts use dedicated green tokens and deletions use red, independent of theme accent or syntax palette. Whole-turn summary has undo/reapply and opens a dedicated changes panel. On narrow panels secondary controls move to More; mobile popovers remain within the native modal.
- Latest-turn patches, worktree/index/HEAD scopes, commits and branch merge-base comparisons are distinct choices. No synthetic patch is used for undo. Confirmation pins the turn and patch; operations refuse conflicts, preserve index state, and cannot silently retry an uncertain command.
- Retryable upstream events replace the working status. Terminal model errors occupy a compact, background-free row within the current conversation, never a global banner; explicit retry continues the failed conversation and preserves any composer draft. Unconfirmed submission errors keep the draft and do not offer an invented retry RPC.
- Context tokens use decimal K/M shorthand with a space on both sides of the slash, such as 272K / 1M. Counts and capacity remain server-derived; exact counts are available on hover.

## Visual consistency pass (2026-09-30)

- Color is token-only. Filled controls (send, stop, primary buttons, effort fill) share `--accent-fill`/`--accent-fill-hover`/`--on-accent`; raised surfaces use `--surface`; status tints use `--danger-soft`/`--danger-ink`, `--warn-soft`/`--warn-ink` and `--notice-ink`. Dark mode redefines tokens instead of overriding component selectors. New components must not hard-code `#fff` or hex surfaces.
- CJK text never goes below 12px. When space is tight, hide secondary text instead of shrinking it. Pure numerals/codes may stay at 11px.
- While no device is connected, the sidebar empty state and the composer's action slot each offer one connect action (connect the last device, or add one); model, effort and context controls appear only once connected.
- Settings panes share one flat section style: 14px/600 headings reuse the navigation label, rows are divided by hairlines without card fills, inputs use the 12px control radius and 44px height. The save bar appears only on Codex panes. Closing with unsaved Codex changes shows an inline "放弃更改 / 继续编辑" choice in the footer. Choice grids use radiogroup semantics with accent-soft selection. Below 560px the settings navigation becomes horizontal rows above the content.
- Expanded command details are indented, with only a hairline between command and output; no bordered card or side rail.
- The Fast service tier is labeled 快速模式, and its active state appears as a small filled lightning mark on the effort trigger.

Current interaction refinements:
- Project location and compact goal share one row. Paused goals expose resume; /goal alone opens management, a supplied objective starts directly, /goal edit restores the objective, and /goal status expands details for eight seconds.
- Completion lists replace the island with icon/name/description/scope rows and bottom tabs. Only actual pending content adds pages; hidden approval drafts survive navigation.
- Device rows report independent connection and activity states. Switching retains background transports and restores device-specific input drafts.
- ToggleSwitch uses explicit track/thumb geometry and a white thumb in both themes, with keyboard focus, reduced motion and forced colors.
- Credentials persist in private server records bound to exact endpoints. Browser metadata retains only opaque references; save/replace/clear states are explicit.
