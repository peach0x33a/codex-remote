# Codex Remote

一个使用 **Vue 3 + TypeScript + Vite + Bun** 构建的 Codex App Server Web 客户端。支持 PWA 安装、保存多台设备，以及连接本机 daemon 的 Unix socket 或远端 WebSocket 地址。

界面参考 DeepSeek 的轻量聊天布局：浅色侧栏、蓝色强调、居中输入区、中文文案与移动端抽屉。使用独立图标和品牌设计。

## 启动

已在 Bun 1.3.14、Node.js 24 和 Codex CLI 0.159.0 环境验证。建议使用 Bun 1.3.14+；Vite 构建工具需要受支持的 Node.js 版本（22.12+ 或 24+）。

~~~sh
bun install --frozen-lockfile
bun run dev
~~~

开发页面是 http://localhost:5173，Bun 桥接服务是 127.0.0.1:3001。只需启动上述一个命令，两个进程会一起运行、一起退出。端口已占用时：

~~~sh
WEB_PORT=5174 BRIDGE_PORT=3002 bun run dev
~~~

验证安装、离线缓存或正式使用时运行生产构建：

~~~sh
bun run build
bun run start
~~~

打开 http://localhost:3000。默认只监听本机，不对局域网或公网开放。构建产物在 dist/；Bun 同时提供静态页面和 /api 连接服务，不能只把 dist/ 上传到纯静态托管后就直接连接 daemon。

更新后若提示设备配置接口 `/api/profiles` 或旧凭据接口 `/api/credentials` 不存在，请确认实际提供 `/api` 的 Bun 后端也已更新。`bun run build` 只更新构建产物；已运行的 `bun run start` 不会自动加载新后端代码，刷新页面或只重启 Vite 也不会更新它。

- 生产模式：由原启动终端或服务管理器停止旧实例，再从本项目目录、沿用原部署环境运行 `bun run start`；托管部署应通过原服务管理器重启，保留原端口、访问控制和凭据存储路径。
- 开发模式：`bun run dev` 会同时启动带 `--watch` 的 Bun 后端和 Vite。若后端没有重新加载，由原启动终端退出该开发命令，再沿用原 `WEB_PORT`、`BRIDGE_PORT` 等配置运行 `bun run dev`。Vite 的 `/api` 代理目标必须与 Bun 的桥接端口一致（默认 `3001`）。

接口不可用时保存或清除操作会报错，连接弹窗保留输入供重试，不会改为把令牌存进浏览器。若错误是“保存的连接凭证不存在”，则是已保存凭据缺失，应重新填写令牌，不能据此判断后端缺少接口。

## 连接已有 daemon

在 Bun 所在机器上启动 Codex daemon：

~~~sh
codex app-server daemon start
~~~

打开顶栏的设备下拉框，选择“添加设备”，填写设备名称和 Unix socket 的**绝对路径**。默认控制 socket 通常在 ~/.codex/app-server-control/app-server-control.sock；自定义 CODEX_HOME 时请使用对应目录。

~~~text
unix:///home/me/.codex/app-server-control/app-server-control.sock
~~~

这里的路径属于 **Bun 服务所在机器**。Unix 方式适用于支持 Unix socket 的系统；Windows 可使用 TCP WebSocket 方式。

## 连接 WebSocket App Server

也可以单独启动一个 TCP 监听器：

~~~sh
codex app-server --listen ws://127.0.0.1:4500
~~~

保存地址 ws://127.0.0.1:4500。127.0.0.1 指向 Bun 所在机器，不是打开网页的手机。

对于其他机器，使用其实际 ws/wss 地址。公开访问应通过 TLS 提供 wss，并按官方文档为 App Server 配置 capability-token 或 signed-bearer-token 认证。将对应的 Bearer token 填入“访问令牌”；**这不是 OpenAI API key**。Codex 自身的模型提供方登录仍由 daemon 所在环境管理。

本项目不会启动、停止或升级你的 daemon，也不使用第一方 remote-control 配对服务。

## 为什么需要 Bun 桥接

官方 App Server 会拒绝携带 Origin 的连接，传输认证通过 Authorization 请求头完成，而浏览器原生 WebSocket 无法任意设置这个头。实际连接链路是：

~~~text
Vue / 已安装的 PWA
  → 同源 Bun WebSocket 连接服务
  → Unix socket 或 ws/wss
  → 你的 Codex App Server
~~~

Bun 使用一次性短时 ticket 完成浏览器握手，将令牌放到上游 Authorization 头中；上游连接不会携带浏览器 Origin。不会把上游令牌塞进 WebSocket URL。

## 外观、审批与消息操作

右上角“设置”打开通用设置弹窗，按连接、外观、背景和内容宽度分组。“自动连接”默认开启，打开页面并完成访问认证后连接上次使用的设备；关闭后等待手动选择设备，手动断开不会被启动逻辑重新连接。设置保存在当前浏览器，按 Escape 可关闭并回到入口。

项目选择器位于输入框上沿的附着式浮岛。菜单显示搜索、项目列表、添加项目和“不在项目中工作”；不指定项目时使用服务器默认工作目录。收到权限审批或 Ask 问题时，浮岛展开并隐藏项目选择，一次显示一张卡片；箭头切换，处理后自动显示下一项，尚未提交的回答会保留。

自己的消息下方提供编辑和撤回入口。编辑可以保留图文顺序后重新发送；撤回会确认影响范围。服务端按整轮回退，因此该轮及其后的会话记录会被移除，已经执行的命令和文件修改不会还原。有任务执行时先停止任务；本页队列暂停并保留。存在服务端待发送消息时需先处理队列，避免回退期间自动启动下一条。服务端不支持回退时不会仅在页面上隐藏消息；重发失败会保留编辑内容。运行中补充到同一轮的消息需要从该轮首条消息操作。

思考正文只展示服务端提供的数据。只有耗时而没有正文的记录不显示，也不显示占位说明。

## 工作目录和运行中调整

首页输入区域固定为 760px 的最大外宽（小屏自适应），与用户的内容宽度设置独立。点击/聚焦编辑器、选择项目或打开会话时，输入框保持同一 DOM 节点，以 420ms 的宽度和位移动画进入对话布局；新对话恢复首页窄宽。减少动态效果偏好禁用空间动画。

运行期间 Enter 向当前任务补充消息（turn/steer）；Tab 或队列按钮加入待发队列。只有服务端明确表示当前任务不可插话（如压缩或审查）才转为排队；超时或发送结果未知时不重复提交。

输入框上方的文件夹按钮是工作目录入口，可以选择已有项目或输入绝对路径。也可以在侧栏项目上开启新对话。切换到另一目录会建立新对话，不改变正在执行任务的目录。

运行中选择模型、思考强度和权限，应用于后续消息，不会修改已经发出的模型请求。支持原生队列的 daemon 通过 thread/settings/update 保存后续设置，通过 thread/queue/add/list/update/delete 管理持久化消息，并由服务端自动调度；网页不再重复派发这些消息。连接同一 daemon 的客户端共享同一线程队列。协议没有逐条模型快照或持久化暂停，页面只在空闲时提供“开始下一条队列消息”。

原生接口不可用时保留标注清楚的本页队列：仅当前页面内存保存，断线、发送结果不明或手动停止后暂停，手动继续；已经确认结束的普通失败允许继续派发下一条。任何结果未知的添加都不会自动重发。存在待发消息时不可归档对应会话、移除对应设备；本页队列和编辑草稿会阻止 PWA 更新。

当前 codex-rs 源码已包含持久化队列和 CLI 提交入口，但原生 TUI 的待发预览仍使用自身输入队列，并忽略 thread/queue/changed。服务端共享已接入不代表 TUI 待发列表已同步；各端必须连接同一个支持实验队列接口的 daemon。

## 任务中心与近期项目

右上角“任务中心”展示当前设备最近活跃的会话，可按状态筛选，并按项目、状态或模型分组。选择任务可查看真实状态、最近消息、工作目录、分支和服务端返回的 Token 用量；点击“打开会话”才进入该会话。仅查看中心不会恢复冷会话或启动队列。页面隐藏、关闭中心或断开设备时停止轮询。

侧栏项目与任务中心使用同一日期规则：以所读取会话中最新的活动日期为基准，包含该日和前一天（浏览器当地时区）。例如最新会话在 9 月 29 日，则只读取 9 月 28–29 日，不根据今天倒推。优先按 recency_at 降序读取，旧版本明确不支持才回退 updated_at；遇到窗口之外的旧记录便停止翻页，不扫描全部历史。搜索也限定在已读取的近期窗口。密集窗口设有单次读取上限，侧栏保留继续读取入口，中心显示未完整读取提示。

下拉选择统一使用自绘菜单，遵循浅色/暗色主题与页面圆角；任务中心分组支持方向键、Home/End、键入匹配、Enter 选择和 Esc 关闭。

collabAgentToolCall 根据实际 tool 解析为创建子代理、发送指令、恢复、等待、关闭、发送消息、后续任务、中断和查看列表。展开显示服务端提供的任务说明、目标代理、模型、强度、代理状态及结果；区分工具调用完成与代理任务完成，未知工具保留名称，不默认输出原始 JSON。

## 输入命令、文件提及与目标

输入行首 `/` 打开命令菜单，可搜索并用方向键、Enter 或 Tab 选择，Esc 关闭。支持 `/goal`、`/new`、`/model`、`/effort`、`/permissions`、`/project`、`/tasks`、`/settings`、`/help`。这些命令打开对应界面，不作为聊天消息发送。

在文字中输入 `@` 搜索当前设备工作目录内的文件。选中后按 Codex TUI 的方式在光标处插入路径，含空格的路径加引号，并保留前后文字和图片；电子邮箱和中文输入法组词不会误触发搜索。

`/goal` 或 `/goal 目标内容` 设置目标和可选 token 预算。目标、状态、实际用量及耗时显示在输入框浮岛；审批或 Ask 请求出现时优先显示请求。点击编辑可修改、暂停、继续或移除目标。目标由服务端保存和推进，通过 `thread/goal/get/set/clear` 与通知同步；启动前等待当前模型和权限设置确认，不额外发送 `turn/start`。需要 daemon 启用 `goals` 功能并支持实验接口，不支持时会明确提示并保留草稿。

## 工具记录与会话详情

工具调用使用无气泡的紧凑行，正常调用不附加完成标识，失败显示红色“× 失败”。只合并相邻同类工具调用，不跨消息、思考条目或轮次；MCP 按服务和工具名区分。读文件依据服务端 `commandActions` 分类，按路径去重显示“已读取 X 个文件”，默认折叠，展开保留每次调用的命令、高亮、输出和错误。

有子代理或文件变更时，宽屏右侧显示会话详情，也可从顶栏开关打开或收起；窄屏以弹窗打开。“创建文件或站点”提供文档、演示文稿、电子表格和站点四项，将请求追加到输入框，不会自动发送。子代理默认显示 6 个，查看更多时再读取其元数据，点击可看真实状态、结果并打开会话。仅查看详情使用有界的只读查询，不恢复子代理或扫描全局项目。

文件变更汇总仅显示最近一轮，下一轮开始即隐藏；默认展示 3 个文件，并使用文件类型图标、绿色新增和红色删除。右侧变更面板支持统一/并排/自动布局、跳转文件、文件目录、内容搜索、换行、全部折叠、刷新和复制补丁。范围包含上一轮、未提交、未暂存、已暂存、提交及分支；分支比较基点为 merge-base，目标是当前工作区。完整的本轮补丁优先来自 turn/diff/updated；没有完整补丁时仅展示已记录的变更，不推断可撤销内容。

撤销/重新应用作用于本轮完整工作区补丁，需要远端 Git 和 Python 3。用户确认后检查整个补丁及目标文件是否冲突，再执行逆向/正向应用；不修改暂存区或会话历史，不自动覆盖冲突或重试结果不明的操作。读取上限 2 MiB，撤销上限 512 KiB；提交列表最多 50 条、分支 100 条、未跟踪文件 64 个，超过范围会明确提示。二进制、软链接等不支持安全回退的情况不会提供有效撤销按钮。

设备默认工作目录留空时使用 `~/codex-remote`；“不在项目中工作”也使用该设备的默认目录。连接设备时不要求目录存在，也不创建目录；首次使用默认目录新建会话或启动目标时，才在远端解析 `~` 并创建目录。优先使用原生文件系统接口，旧 POSIX 服务的兼容命令从已存在的 `/` 启动。创建失败会保留连接与草稿，仍可查看历史、选择已有项目或修正权限后重试；不会静默切换到其他目录。手动选择的项目不会被自动创建。

局域网 HTTP 环境不暴露 `crypto.randomUUID` 时，客户端使用 `crypto.getRandomValues` 生成 UUID v4，设备保存、消息发送、附件和其他标识生成均可正常工作。原生 `subAgentActivity` 的 started/interacted/interrupted/completed 事件显示为子代理活动卡片，保留代理路径和会话标识；交互事件的结束时间不等于子代理任务完成。

暂停、受阻及用量受限的目标均显示“恢复目标”按钮；恢复只更新目标状态，不改目标正文、已有计数或预算。额度是否已恢复仍由 App Server 判定。目标预算耗尽时会打开预算编辑，要求确认高于已用 tokens 的新预算后“保存并恢复”，不会自动增加限额。

上下文容量窗口显示当前真实 Session ID，并提供“复制”按钮；右上角会话菜单不再重复提供 Session ID 入口。复制仅由用户点击触发，兼容允许旧式复制的 HTTP 浏览器；失败只提示，不自动打开窗口或选中显示的 ID。

手动停止的轮次在其末尾显示“已停止 · 工作了 …”，没有最终回复也可显示。优先使用服务端时间；缺失时只冻结已观察到的真实运行时间。历史记录没有可用时长时不猜测数字；下一轮输入不会被算到上一轮的停止信息中。

桥接将短暂的 WebSocket 背压视为正常排队，按序等待发送缓冲排空，不重发已入队的消息。发送缓存与待发队列合计限制为 16 MiB（含帧开销）；仍有发送进展时继续等待，持续 30 秒没有进展、缓冲超限或消息确实丢失时才断开并提示重新同步。

## 保存与隐私

- 设备名称、App Server 地址、默认目录及所选设备统一保存在 Bun 服务端。登录同一服务的浏览器共享设备列表；打开页面、切回窗口及每 10 秒自动刷新。其他客户端切换设备不会打断当前页面正在查看的会话。
- 旧版浏览器设备记录会在登录后自动迁移；按地址去重，不覆盖服务端已有配置，全部迁移成功后删除浏览器中的旧记录。失败时保留原记录并提示重试。
- 连接设置中的“记住令牌”默认开启：设备配置与令牌一同保存在 Bun 服务端的 `.local/credentials.json`（文件权限 `0600`），以原子事务新增、修改和移除。浏览器不再持久化设备或凭据编号，接口只返回设备配置和不透明引用，不返回令牌。可通过 `APP_CREDENTIALS_FILE` 指定私有持久路径；容器部署应挂载该文件所在目录。
- 取消“记住令牌”后仅在当前页面内存中使用。已保存的令牌不会回传或回填浏览器；留空可保留，填新值可替换，也可选择“清除已保存令牌”后保存。移除设备同时清除服务端令牌。凭据绑定精确的 App Server 地址，不能随地址修改而被发送到其他主机。
- App Server 保存会话；此 Web 客户端不把聊天记录写入 localStorage 或 service worker 缓存。
- Markdown 禁用原始 HTML，并经过 DOMPurify 清理。模型输出中的远程图片不会自动加载。
- Bun 是受信任的一方；不要把自己的 App Server 令牌交给不可信的桥接部署。

## PWA 和部署

Chrome/Edge 可点击“安装应用”或浏览器菜单中的安装入口。iPhone/iPad 使用 Safari 的“分享 → 添加到主屏幕”。远程设备安装需要 **HTTPS**；localhost 开发环境例外。

第一次联网打开后，静态页面、字体和图标会缓存。离线可打开已缓存的界面；**设备列表读取/保存、连接、会话加载和模型执行需要网络**。更新通过右上角可点击 toast 手动应用，不显示横幅；任务进行中禁用更新操作。

如果将应用放在反向代理后，参考 .env.example 配置：

~~~dotenv
HOST=127.0.0.1
PORT=3000
APP_ORIGIN=https://codex.example.com
APP_ACCESS_KEY=replace-with-a-long-random-password
# 可选，限制允许访问的上游主机名；不含端口：
APP_ALLOWED_HOSTS=127.0.0.1,localhost,codex.internal.example
# 可选，禁用本机 Unix socket：
ALLOW_UNIX_SOCKETS=false
~~~

请替换示例访问密码。非 loopback 监听或公开域名必须设置 APP_ORIGIN 和至少 16 字符的 APP_ACCESS_KEY。密码验证后使用 HttpOnly / SameSite cookie；HTTPS 部署还会设置 Secure。来源校验同时作用于 HTTP 请求和 WebSocket 握手，登录有失败频率限制。

例如，使用 Caddy 将同一站点完整转发到 Bun（包括 /api 和 WebSocket）：

~~~caddyfile
codex.example.com {
    reverse_proxy 127.0.0.1:3000
}
~~~

本应用面向自己的可信设备，是共享后端权限的单用户工作空间，不提供多租户权限隔离。放在不受信任网络时，可配置上游主机白名单，按需要关闭 Unix socket。

## 验证

~~~sh
bun run typecheck
bun run test
bun run build
bunx playwright install chromium
bun run test:e2e
~~~

默认测试套件保留 648 项（619 单元、29 集成），浏览器套件保留 84 项（桌面/手机各 42）。重点保护协议状态、认证/凭据、跨设备隔离、队列、文件读写及主要交互；相同边界不再反复展开大量展示参数。

浏览器测试使用独立的 loopback mock bridge 和 `.local/e2e-credentials.json`，不会继承生产 `.env` 中的访问密码或凭据路径。如果主目录正在运行服务，可以使用独立构建目录避免覆盖线上静态文件：

~~~sh
bun ./node_modules/vite/bin/vite.js build --outDir .local/e2e-dist --emptyOutDir
E2E_STATIC_DIR=.local/e2e-dist bun run test:e2e
~~~

如果已有 Chromium，可以设置 CHROMIUM_PATH；测试端口默认 14731 和 14501，可用 E2E_PORT / MOCK_PORT 更改。模拟 daemon 仅存在于 tests/，不会打包到生产代码中。

可对一个明确指定的真实 daemon 做只读协议验证：

~~~sh
bun scripts/smoke-daemon.ts unix:///absolute/path/app-server-control.sock
~~~

默认验证只做 initialize、model/list、thread/list。追加 --history 可验证一个未运行会话的元信息恢复和分页读取。两种方式都不启动 turn、不执行代码、不打印对话内容。

## 范围与兼容性

- App Server WebSocket 协议仍属实验性；实现依据官方文档和本机 CLI 0.159.0 的生成类型。
- 会话恢复使用 thread/resume（excludeTurns: true）、thread/turns/list 和 thread/items/list。旧服务器仅在明确不支持分页方法时回退到原有恢复方式。
- “帮我批准”将 approvalsReviewer 设为 auto_review，并保留工作区沙盒；不会将自动审批映射成完全访问。自定义权限从已恢复会话继承。
- MCP elicitation 表单与客户端动态工具不在当前范围；不支持的请求会明确拒绝或返回方法不支持，不会自动批准执行。
- 真正的桌面/手机安装按钮由浏览器控制；自动测试覆盖 manifest、图标、service worker 接管与离线重载，不声称已在每种 OS 的桌面上手工安装。

### 背景外观

背景与外观主题独立：切换浅色、暗色或系统主题，不会切换动效、图片或纯色背景，也不会改变图片的不透明度、模糊、叠加颜色和颜色强度。旧版分主题设置按升级时正在显示的背景迁移一次。动效在欢迎页与对话页保持连续；上传图片及效果可单独调整、重置。图片保存在浏览器 IndexedDB，调整值保存在本地偏好中。上传后的 Blob 图片需要当前后端响应包含更新后的 img-src blob: 策略。
